# Hermetic Fixtures

Use this when tests spawn the real CLI, read configuration, cache remote
data, or would otherwise touch the network or the developer's machine.

## No Network, Proven
`assets/templates/conftest_hermetic.py` installs an autouse fixture that
replaces `socket.socket.connect` with a function that raises. Every test is
offline unless it is marked `@pytest.mark.allow_network` and says why in its
docstring. `assets/templates/test_hermetic_control.py` is the control: it
asserts a connect raises, that `HOME` is a temp path, and that the marker
restores the real connect. If the guard is deleted, the control fails.
Measured 2026-09-20 on the template: 3 passed with the guard; the first case
fails without it.

`filterwarnings = ["error"]` in the pytest config means an unclosed socket
after a refused connect surfaces as a test failure; open sockets in tests
with `with socket.socket() as sock:`.

## Isolate Config and State
- `HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` point at `tmp_path`; the CLI
  is pointed at a per-test config via `--config` or `<TOOL>_CONFIG`.
- Tests never read or write the real cache, output, or workspace-root
  configuration. A test that needs a cache creates one under `tmp_path`.
- Diagnostics (`doctor`) are tested for creating nothing: snapshot
  `sorted(tmp_path.rglob("*"))` before and after.

## Recorded Inputs Replace Live Services
- Record once, by hand, with the real tool and a stated command; commit
  under `fixtures/<source>/<content-hash>.json` with a sidecar `.meta.json`
  (URL or query, timestamp, size, tool version, licence/attribution).
- The acquisition layer takes a cache directory; tests point it at
  `fixtures/` in read-only mode and any miss is an error, never a fetch.
- Keep fixtures small enough to review: a bounding box a few hundred metres
  across, not a city. A "large" fixture for the scale lane is generated by a
  checked-in script from the small one, not recorded.
- Fixture hashes are goldens too: a changed fixture is a golden update with
  an approval record.

## Subprocess Fixtures
- Spawn with `[sys.executable, "-m", "<pkg>.cli", ...]` so the test uses the
  interpreter and environment pytest runs under; use the installed entry
  point (`uv run <tool>`) only in the contract lane and say so.
- Always `capture_output=True, text=True, timeout=<seconds>, check=False`
  and assert on `returncode`, `stdout`, and `stderr` separately.
- Pass `env={**os.environ, "PYTHONIOENCODING": "utf-8", ...}` explicitly
  when an environment variable is part of the contract under test.

## Backward-Compatible Fixture Evolution
- New fields in serialized fixtures or scene JSON are optional with a
  default in the dataclass, so older recorded inputs still parse.
- Update fixture builders intentionally and only for the evolved type; a
  helper that fabricates plausible values for every new field hides
  migration bugs.
- When a fixture format changes incompatibly, bump the directory
  (`fixtures/overpass-v2/`) rather than rewriting files in place.
